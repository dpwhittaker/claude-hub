# Hindsight — optional long-term memory for claude-hub sessions

**claude-hub does not need this.** The proxy, terminals, file viewer and project
creation all work with none of it installed. Hindsight is an enhancement: it gives
every Claude session in `~/projects/` a per-repo memory bank, so a session that
starts cold can be told what this repo decided six weeks ago and why.

It is documented here rather than in `AGENTS.md` because it is *harness-level* —
it lives in `~/.hindsight/` and `~/.claude/`, not in this repo — but it is
rebuilt from this machine and nowhere else records how.

Rebuilding the box? Do the rest of the README first, confirm claude-hub serves,
then come back here. Nothing below is required for a working hub.

---

## What it gives you

Each git repo resolves to a memory bank. Three things feed it, all in the background:

| Source | What lands |
|---|---|
| **git ingest** | commit messages (`gitlog:<repo>` doc, re-upserted as HEAD moves) |
| **session write-back** | your transcripts, retained on every `Stop` |
| **codebase survey** | 4 structural docs from a one-off headless agent (component map, core concepts, conventions, tech stack) |

A server-side consolidation pass synthesizes those into **5 knowledge pages** per
bank. Agents read the pages through MCP tools (`hindsight_search_knowledge_pages`,
`hindsight_read_knowledge_page`, `hindsight_reflect`).

Nothing is injected into the context automatically except a short page roster at
session start — see `autoReflect` below for why.

## Install

### 0. Prerequisite: binaries must resolve without a login shell

Hooks are spawned by Claude Code, whose `PATH` is
`/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/snap/bin` — **no `~/.local/bin`,
no nvm.** Two things must therefore exist before anything below works:

- `/usr/bin/{node,npm,npx}` → `/usr/local/bin/nvm-shim` (see the user-level
  `CLAUDE.md`). The installed hooks are written as bare `node "<abs path>"`.
- `/usr/local/bin/claude` → `~/.local/bin/claude`. The codebase survey resolves
  `claude` off `PATH`, and **a missing binary is a silent no-op** — the survey
  simply never runs and logs nothing.

Verify both the way a hook sees them:

```bash
env -i PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/snap/bin \
  bash -c 'node -v && claude --version'
```

### 1. Server

Installed with `uv` into its own venv, with an embedded Postgres:

```bash
uv pip install --python ~/.hindsight/venv/bin/python hindsight-api==0.9.2
sudo install -m 644 ~/.hindsight/hindsight.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now hindsight.service
curl -s http://127.0.0.1:9077/version
```

Config is `~/.hindsight/hindsight.env` (an `EnvironmentFile=`, not a shell script).
Two lines in the unit are load-bearing and easy to lose:

- `Environment=LD_LIBRARY_PATH=/home/david/.pg0/installation/18.1.0/lib` — the
  embedded Postgres binaries were built against ICU 70; this host ships ICU 78, so
  `postgres` fails to start without it. Drop the line only if the cluster is
  re-provisioned against a matching system Postgres.
- `After=ollama.service` — ordering only, so the first retain after an unattended
  boot doesn't fire while Ollama is still finding the GPU.

Migrations run automatically at startup. Watch them once:

```bash
journalctl -u hindsight.service -f | grep -i 'alembic\|migration'
```

### 2. Ollama

The source of truth for the drop-in is `~/.hindsight/ollama-override.conf`; the
unit itself is generated by Ollama's installer and is overwritten on upgrade.

```bash
sudo install -m 644 ~/.hindsight/ollama-override.conf \
  /etc/systemd/system/ollama.service.d/override.conf
sudo systemctl daemon-reload && sudo systemctl restart ollama
ollama pull VladimirGav/gemma4-26b-16GB-VRAM
```

That file carries the tuning and the reasoning behind it — read it rather than
re-deriving. Summary: flash attention on, `q8_0` KV cache, `OLLAMA_NUM_PARALLEL=3`.

### 3. Client

```bash
npx @vectorize-io/hindsight-coding-agents install claude-code
```

Writes 3 hooks into `~/.claude/settings.json` (SessionStart, UserPromptSubmit,
Stop), registers the MCP server via `claude mcp add --scope user`, and installs a
companion skill. Re-running the same command is how you update it.

**Write `~/.hindsight/coding-agent.json` before the first session** — see the next
section for why the timing matters.

## Configuration — and why each value is what it is

One file: `~/.hindsight/coding-agent.json`.

```jsonc
{
  "serverMode": "self-hosted",
  "apiUrl": "http://127.0.0.1:9077",
  "bankIdTemplate": "cc-{gitProject}",
  "autoReflect": false,
  "banks": {
    "cc-genesis":             { "pageTriggerType": "cron", "pageTriggerCron": "0 16 * * 0" },
    "cc-bema":                { "pageTriggerType": "cron", "pageTriggerCron": "0 16 * * 0" },
    "cc-systematic-theology": { "pageTriggerType": "cron", "pageTriggerCron": "0 16 * * 0" }
  }
}
```

**`bankIdTemplate: "cc-{gitProject}"`** — load-bearing. The package default is
`coding-agent::{gitProject}`. This machine's banks were created by an older
integration under a `cc-` prefix and hold tens of thousands of memories; the
template is what keeps the new client pointed at them instead of silently starting
empty ones. Do not remove it on a rebuild if the old banks are being restored.

**`autoReflect: false`** — required here, not a preference. The automatic
session-start reflect is capped at a hardcoded 25s (`HOOK_REFLECT_CAP_MS`, applied
as `min(reflectTimeoutMs, CAP)` — no config raises it). Measured against the local
model, reflect takes ~50s warm, so every session's first prompt burned 25s and
returned nothing. With this off, memory is pull-based: the agent calls
`hindsight_reflect` on demand, which is *not* capped (330s tool timeout, high
budget). Revisit only if a faster reflect model is configured.

**`banks.<id>` cron** — weekly page refresh, Sundays 10:00 CST, for the teaching
repos only. The default `auto-refresh` regenerates every page after every
consolidation, which on one GPU with `MAX_CONCURRENT` set low keeps the card busy
more or less continuously.

> `pageTriggerCron` is **UTC and DST-blind**. `0 16 * * 0` is a literal 10:00 CST,
> which reads as 11:00 local during daylight saving.

> **Page triggers apply only to pages created from here on.** Changing this later
> does not migrate a bank's existing pages — each keeps the trigger it was born
> with and needs `PATCH /v1/default/banks/<bank>/knowledge-base/nodes/<id>` to
> move. On a rebuild, write this file *before* the first session in each repo.

### Cadence settings worth revisiting per repo

`surveyRefreshCommits` (default 20) re-runs the structural survey once that many
commits accrue. It counts **commits, not days**, so the right value depends
entirely on a repo's rhythm — 20 commits is ~28 days in a repo committed daily and
~78 days in one touched a few times a month. Pick whatever ≈ 2–4 weeks *there*, per
bank. There is no cron option for the survey: its only trigger is SessionStart.

`pageRefreshEveryTurns` (default 10) re-injects the page roster every N user turns.
Sessions shorter than N never reach it, which is harmless — SessionStart injects
the roster once regardless.

## Verifying a rebuild

```bash
# 1. Server up, on a version that has knowledge pages
curl -s http://127.0.0.1:9077/version
curl -s http://127.0.0.1:9077/openapi.json | grep -c knowledge-base   # expect > 0

# 2. Model resident, fully on GPU — size must EQUAL size_vram
curl -s http://127.0.0.1:11434/api/ps

# 3. Client wired to the right bank
#    (from inside a repo; or call the hindsight_diagnose MCP tool)
grep -A2 hindsight ~/.claude.json

# 4. Ingestion progressing — hindsight_sync_status, or:
curl -s "http://127.0.0.1:9077/v1/default/banks/cc-<repo>/knowledge-base/tree"
```

Diagnostics live in two files: `/tmp/hindsight-plugin.log` (structured JSON, one
line per reflect/page/survey outcome) and `$TMPDIR/hindsight-coding-agent/plugin.log`
(leveled, human). **Every failure mode here degrades silently by design** — a
memory-less session looks exactly like a healthy one — so these logs are the only
way to tell the difference.

## Gotchas

**Everything fails quietly.** A missing binary, an unreachable server, a reflect
timeout: all no-op so the agent is never broken by its memory layer. That is the
right call for a background enhancement and it makes every problem here a
*log* question, never a symptom you'll notice in the session.

**The GPU is shared.** The model resides at ~14.97 GB on a 16 GB card, leaving a
few hundred MB. If `/api/ps` ever reports `size != size_vram`, or the Ollama log
shows fewer than all layers offloaded, reduce `OLLAMA_NUM_PARALLEL` — CPU spill
costs far more than the parallelism gains. Reduce
`HINDSIGHT_API_LLM_OLLAMA_NUM_CTX` before reducing slots.

**Two things must not be pointed at the subscription.** Extraction and
consolidation run on every retain. Confirm they are local:

```bash
curl -s http://127.0.0.1:9077/metrics | grep '^hindsight_llm_calls_total'
# every line must read provider="ollama"
```

A backfill on a metered provider once burned most of a monthly limit in a morning,
and it did not show up in `/cost`.

**The survey never reads `AGENTS.md` or `CLAUDE.md`** — by design. They are live,
user-controlled instructions, and a stale copy captured as memory could override
the current ones. Don't "fix" this by feeding them in.

**`/clear` starts a new session; `/compact` does not.** Session state is keyed on
session id alone, so `/clear` resets the turn counter and page-roster cadence.
Nothing is lost — write-back happens on every `Stop`, not at session end.

## Backup and restore

The bank database is the only durable state; everything else is reinstallable.
There are no client-side files worth keeping.

```bash
# Back up (cold — stop the service first for a consistent copy)
sudo systemctl stop hindsight.service
tar czf ~/.hindsight/backups/pgdata-$(date +%F).tar.gz \
  -C ~/.pg0/instances/hindsight data
sudo systemctl start hindsight.service

# Restore: stop, replace ~/.pg0/instances/hindsight/data, start.
# Migrations run forward automatically on the next boot.
```

Take one before any server upgrade. The 0.8.5 → 0.9.2 upgrade ran 13 migrations,
including the one that creates the knowledge-page tables.

To reset a single repo's memory, delete its bank on the server — the next session
there is a true first open and re-seeds from scratch.

## Removing it

Hindsight is separable, which is the point of documenting it apart from the hub:

```bash
npx @vectorize-io/hindsight-coding-agents uninstall claude-code
sudo systemctl disable --now hindsight.service
```

The first command removes exactly what `install` added (hooks, MCP registration,
skill). claude-hub is unaffected — it never talks to Hindsight, and no route,
unit or project sentinel references it.
